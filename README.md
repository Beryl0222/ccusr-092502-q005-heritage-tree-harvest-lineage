# 古树采后责任谱系

西溪湿地七千余棵古树（扁柿、火柿、方柿）成熟季的采后责任谱系后端。系统为
树木、品种、年度评估、可采范围、作业小组、作业、称重批次、隔离、损伤观察、
去向、交接与修复建立不可混淆的编号和可追溯的事件谱系，支撑“从一棵树追到各次
采收影响”与“果品数量守恒、责任闭环”两类核对。

## 设计原则

- **事实只追加**：所有业务结论都是事件（`src/events.py`），写入 JSONL 日志
  （`src/store.py`）后不再原地改写；更正、隔离、拒收、修订一律以新事件表达。
- **重启即恢复**：服务启动时从日志整体折叠出当前状态（`src/projections.py`），
  待处理的隔离批次与修复计划通过 `pending_work()` 找回并继续处理。
- **编号带类型**：每种实体有固定前缀（如 `tree-`、`batch-`、`xfer-`、
  `care-`，见 `src/ids.py`），跨类型使用编号会被直接拒绝。

## 编号体系

| 实体 | 前缀 | 示例 |
| --- | --- | --- |
| 品种 | `cultivar-` | `cultivar-bianshi` |
| 树木 | `tree-` | `tree-0001` |
| 年度评估 | `assess-` | `assess-0001-a2026` |
| 可采范围 | `range-` | `range-0001-r2026` |
| 作业小组 | `crew-` | `crew-team-a` |
| 采收作业 | `op-` | `op-op-1` |
| 称重批次 | `batch-` | `batch-b001` |
| 损伤观察 | `obs-` | `obs-obs-1` |
| 交接记录 | `xfer-` | `xfer-x1` |
| 修复计划 | `care-` | `care-care-1` |

## 关键不变量（由 `src/domain.py` 强制）

- **离线称重幂等**：以 `(device_id, client_record_id)` 为幂等键。原样重传返回
  原事件、不重复计重；同一离线记录却声称是另一个批次号，属于标识冲突——
  新批次登记后立即 `BATCH_QUARANTINED` 隔离，旧称重记录原样保留，绝不改写。
- **果品去向互斥**：批次只有核查准入（`BATCH_ADMITTED`）后才能登记去向，且
  游客采摘 / 科研留样 / 公益赠送三选一，不能重复登记；非准入批次不得分配去向。
- **数量守恒**：`conservation_report(year)` 核对
  称重总量 = 待处置 + 隔离 + 准入 + 拒收，准入量 = 已分配 + 库存，按渠道汇总
  不重不漏。
- **交接链不断链**：首次交接必须由采收班组交出（原责任人不可跳过），其后每手
  交出方必须等于上一手接收方，交接重量必须等于批次称重，终点必须等于登记去向。
- **树势异常暂停后续作业**：标记异常联动暂停该树进行中的作业，并拦下新开作业
  与称重；已完成的交接、责任人和去向不受影响。
- **年度负荷保护**：作业计划受可采范围剩余量约束，称重受可采范围与年度评估负荷
  双上限约束（隔离/拒收批次的果实也已离树，仍计入负荷）。
- **纠正只局部重算**：`DAMAGE_OBSERVATION_CORRECTED` 追加后，投影自动重算该树
  当年负荷；若关联的修复计划尚未完成，则追加 `CARE_PLAN_REVISED` 重算等级，
  其他树木与已完成修复的责任人不变。

## 代码结构

- `contracts/domain.json`：实体、事件、编号前缀、去向渠道的共享合同。
- `src/envelope.py`：共用事件信封校验（事件标识、聚合、版本、时区时间）。
- `src/ids.py`：类型化编号的构造、解析与跨类型防护。
- `src/events.py`：事件值对象与工厂。
- `src/store.py`：仅追加 JSONL 存储；`event_id` 全局幂等、
  `(aggregate_id, version)` 版本位不可覆盖。
- `src/domain.py`：领域服务，所有命令产出事件并执行业务规则。
- `src/projections.py`：事件折叠、树木谱系、年度负荷、数量守恒与责任闭环报告。
- `tests/test_lineage.py`：完整采收季、幂等与冲突隔离、暂停、局部纠正重算、
  跨重启恢复、存储防护等行为测试。

## 测试与构建

```bash
python3 -m unittest discover -s tests
python3 -m compileall -q src tests
```

两条命令均只使用 Python 标准库，可在单个 Linux 应用容器中直接执行。
